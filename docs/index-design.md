# 색인 설계 (초안)

수집 → 정규화 → 중복 제거 → 저장(Postgres) → 벡터 색인(Qdrant) → 검색의 데이터 구조와 규칙을 정한다.
근거는 [data-sources.md](data-sources.md)의 실측 결과이고, 코드 원칙은 [README.md](../README.md)를 따른다.
**하드코딩하지 않는다**: 변환표·가중치·임계값은 리소스 파일 또는 `@ConfigurationProperties`에 둔다.

> 상태: 초안. 아래 "확인이 필요한 결정"을 정한 뒤 확정하고 코드를 쓴다.

## 1. 공통 모델 (Postgres)

세 소스를 하나의 `Event`로 합친다. 소스는 각자 어댑터에서 `RawEvent`로 바뀌고, 이후 단계는 소스를 모른다.

**event** (실제로 검색되는 하나의 행사)
| 필드 | 설명 |
|---|---|
| `id` | UUID. 벡터 색인의 point ID와 같다 |
| `kind` | 공연 / 전시 / 축제 (3종) |
| `category` | **표준 분류 코드** (아래 3절). 소스 이름이 아니라 우리 코드 |
| `title`, `title_norm` | 표시용 제목, 중복 판정용 정규화 제목 |
| `description` | 설명 (없을 수 있음) |
| `start_date`, `end_date` | 날짜. 소스별 형식 차이는 수집 단계에서 통일 |
| `venue_id` | 장소 (아래) |
| `region_code` | **법정동 코드 5자리(시도 2 + 시군구 3)**. 시도만 알면 시군구는 비움 |
| `lat`, `lon` | 좌표. 소스마다 순서가 달라 저장 전에 통일 |
| `price_type`, `price_text` | 무료/유료/알 수 없음, 원문 문장 |
| `age_text`, `runtime_text`, `schedule_text` | 관람 연령·시간 안내 원문 |
| `ticket_links` | 예매처 이름과 링크 목록 (KOPIS `relates`) |
| `image_url`, `image_license` | 대표 이미지와 이용 조건(TourAPI 저작권 유형 등) |
| `status` | 예정/진행 중/종료. **날짜로 계산**하고 저장은 갱신 편의용 |
| `embed_hash` | 임베딩 텍스트의 해시. 바뀔 때만 다시 임베딩한다 |

**event_source** (한 행사가 여러 소스에서 왔을 수 있다)
`event_id`, `source`, `source_id`, `source_updated_at`, `fetched_at`, 원본 응답(JSON).
- 출처 표시 의무(KOPIS 등)와 문제 추적을 위해 **원본과 출처를 항상 보존**한다.

**venue** (장소: 공연장·박물관·행사장)
`id`, `name`, `name_norm`, `address`, `region_code`, `lat`, `lon`, 소스별 장소 ID, 편의시설·접근성 플래그(KOPIS 공연장에서).
- KOPIS는 공연장 조회에서, 문화정보원은 `placeAddr`·`placeSeq`에서, TourAPI는 행사 자체의 주소·좌표에서 만든다.

**ingest_run** (수집 실행 기록)
소스, 시작·종료, 건수(신규·변경·실패), **매핑 안 된 값 목록**. 데이터 품질 문제가 조용히 묻히지 않게 한다.

## 2. 벡터 색인 (Qdrant)

컬렉션 하나(`tshow-events`), point ID = `event.id`.

**임베딩 텍스트 (의미로 찾는 부분)**: 제목, 분류, 장소 이름, 지역(시도·시군구 이름), 출연·주최, 설명(길면 앞부분), 대상·분위기 태그.
- **날짜·가격은 넣지 않는다.** 바뀌어도 재임베딩이 필요 없고, 정확히 걸러야 하는 값이기 때문이다.
- **설명이 없는 항목이 많다**(KOPIS 하루치 실측에서 9%만 설명이 있음). 설명이 비어 있으면 제목·분류·장소·지역·출연·기획사 등 나머지로 구성하고 `has_description=false`를 payload에 둔다. 같은 행사가 여러 소스에 있으면 병합 때 설명이 있는 쪽을 채택한다. **AI가 없는 사실을 만들어 채우지 않는다** (태그는 있는 텍스트에서만 뽑는다).
- 텍스트를 조립하는 규칙(어떤 필드를 어떤 순서로, 길이 제한)은 코드 상수가 아니라 설정으로 둔다.

**payload (정확히 걸러야 하는 부분)**
| 필드 | 용도 |
|---|---|
| `kind`, `category` | 분류 필터 |
| `region_sido`, `region_sigungu` | 지역 필터 (코드) |
| `location` (위경도) | 반경 필터 (Qdrant geo) |
| `start_ts`, `end_ts` | 날짜 범위 필터 (숫자) |
| `price_type` | 무료 필터 |
| `has_description`, `source_count` | 순위 보조, 품질 |
| `updated_at` | 갱신 추적 |

**검색 순서 (tcine 교훈)**: 날짜·지역·분류·종료 여부 같은 **필수 조건은 벡터 검색 전에 payload 필터로 거른다.** 그 안에서 벡터 + 키워드를 결합하고 순위를 매긴다. 필터를 나중에 걸면 조건에 맞는 행사가 후보에 들어오지 못한다.

**갱신**: 일정·상태·가격·링크가 바뀌면 **payload만 갱신**한다. `embed_hash`가 바뀐 경우(제목·설명 변경)만 재임베딩한다. 종료된 일정은 검색에서 빼되 일정 기간 보관할지는 결정이 필요하다.

## 2-1. 구현 (2026-10-08)

`domain/index` 패키지. 계산 로직과 외부 연동을 인터페이스로 갈라서 로직을 가짜 구현으로 테스트한다 (`VectorIndex`, `Embedder`, `IndexStateStore`).

| 클래스 | 역할 |
|---|---|
| `EmbeddingTextBuilder` | 행사 → 임베딩 문장. 모양은 `resources/index/embedding.tpl`(코드 밖). 값이 없는 줄은 뺀다. 날짜·가격은 넣지 않는다. 설명은 `description-max-chars`까지 |
| `PayloadBuilder` | 필터용 값: kind, category, sido, sigungu, start_day/end_day(에포크 일수), price_type, has_description, source_count, location(위경도). 값이 없는 필드는 넣지 않는다 |
| `IndexService.sync()` | 바뀐 행사만 반영한다. **embed_hash**(임베딩 텍스트 해시)가 바뀌면 다시 임베딩, **payload_hash**만 바뀌면 payload만 갱신(재임베딩 없음), 논리삭제된 행사와 DB에 없는 점은 색인에서 삭제. 일부 실패해도 계속하고 실패한 행사는 상태를 기록하지 않아 다음에 재시도 |
| `QdrantVectorIndex` (`infra/qdrant`) | Qdrant 구현. 컬렉션 생성(코사인, 768차원), 필터 필드 payload 색인(keyword/integer/geo), upsert, payload 덮어쓰기, 삭제, 전체 id 조회, **필터 + 벡터 검색** |
| `SpringAiEmbedder` (`infra/embedding`) | OpenAI `text-embedding-3-small`(768차원, tcine과 같은 설정). API 키가 없으면 색인 단계를 건너뛴다 |
| `JpaIndexStateStore` | `event.embed_hash / payload_hash / indexed_at`에 색인 상태를 저장 (마이그레이션 V4) |

- 실행 순서: 수집 → 병합 → **색인**(`batch/DataPipelineService`, cron은 `PipelineScheduler`). 새벽 수집 뒤에 변경분만 올라간다.
- 컬렉션은 공용 Qdrant 안에서 `tshow-events`(설정 `tshow.index.collection-name`)를 쓴다.
- 검증: 단위 테스트 12건(가짜 구현으로 변경 판정 전반)과 **실제 Qdrant 통합 테스트** `QdrantVectorIndexIT`(`RUN_QDRANT_IT=true`, 로컬 `docker compose up -d qdrant`)에서 날짜·분류·지역·무료·지리 반경 필터와 payload 갱신·삭제를 확인했다.
- 임베딩 호출 비용을 아끼는 장치: 같은 내용이면 다시 임베딩하지 않는다 (`다시_실행하면_바뀐_게_없어_임베딩하지_않는다` 테스트).

## 3. 정규화 — 변환표는 리소스 파일로

| 대상 | 리소스 | 내용 |
|---|---|---|
| 표준 분류 | `taxonomy/categories.yml` | 표준 코드와 이름, **소스별 원본 이름·코드 → 표준 코드** 매핑 (KOPIS 장르 9종, 문화정보원 분야 9종, TourAPI `EV…` 코드) |
| 지역 | `taxonomy/regions.csv` | 법정동 시도·시군구 코드, 정식 이름, **별칭**(서울/서울시/서울특별시, 새 행정구역 이름, `해외` 처리 등) |
| 중복 판정 | `application.yml` | 제목 유사도·장소 유사도·날짜 허용 오차 임계값 |
| 소스 우선순위 | `application.yml` | 필드별로 어느 소스를 우선할지 (예: 설명은 TourAPI·KOPIS, 가격은 문화정보원·KOPIS) |

- 변환하지 못한 값은 **예외로 터뜨리지 않고** `ingest_run`의 "매핑 안 된 값"에 기록하고 기본 분류("기타")·시도 미상으로 저장한다. 표를 고치면 다음 수집부터 반영된다.
- 지역·분류 표에 값이 없을 때 코드 분기로 때우지 않는다.

## 4. 중복 제거와 병합 (구현됨, 2026-10-08)

수집(`source_record`)과 병합(`event`)은 별도 단계다. 병합은 저장된 소스 레코드만 읽으므로 API를 다시 호출하지 않고 **설정만 바꿔 다시 돌릴 수 있다**. 기준값과 필드 우선순위는 모두 `application.yml`의 `tshow.merge.*`.

**판정** (`DuplicateMatcher`, 서로 다른 소스 사이에서만. 같은 소스의 두 레코드는 같은 작품의 다른 공연일 수 있어 합치지 않는다)
1. 시작일이 같고(허용 오차 설정) **기간이 겹친다.** 종료일은 같을 필요가 없다 — 장기 공연은 소스마다 종료일을 다르게 준다 (실측: `2026-10-31` vs `2026-12-19`).
2. 제목(정규화: `[지역]` 꼬리표·괄호·8자리 날짜·HTML 엔티티 제거)의 글자 2-그램 유사도가 0.85 이상이거나, 장소가 같을 때 한쪽 제목이 다른 쪽에 통째로 포함된다(부제 차이, 8글자 이상).
3. 장소가 같다: 이름이 비슷하거나 한쪽이 다른 쪽을 포함하거나 좌표가 300m 안. 장소가 안 맞아도 **같은 시군구에서 제목이 0.95 이상 같으면** 같은 행사로 본다(같은 건물의 다른 이름, 예: `충남도청 문예회관` vs `충청남도 문화예술회관`).
4. 한쪽에 장소 정보가 전혀 없으면 제목이 완전히 같아야 한다.

**묶음** (`Clusterer`): 판정된 쌍을 union-find로 묶되, **한 묶음에 같은 소스 레코드가 둘 이상 들어가게 되면 연결하지 않고 충돌로 센다.** 시작일별로 나눠 비교한다(전체 쌍 비교 방지).

**필드 병합** (`EventMerger`): 필드마다 소스 우선순위(`tshow.merge.priority`)대로 값이 있는 첫 레코드를 쓴다. 제목과 정규화 제목, 장소 이름과 정규화 이름, 가격 문장과 가격 구분, 이미지와 이용 조건, 좌표 쌍은 같은 레코드에서 함께 가져온다. 현재 우선순위: 기본 KOPIS > 문화정보원 > TourAPI, 설명은 TourAPI 우선, 이미지는 KOPIS > TourAPI, 상세 링크는 문화정보원 우선.

**행사 id 안정성**: 벡터 색인의 point id가 되므로 바뀌면 안 된다. 묶음에 이미 행사에 연결된 레코드가 있으면 그 id를 이어 쓰고(여럿이면 가장 작은 id), 묶음이 갈라져도 같은 id를 두 행사에 주지 않는다. 행사에는 내용 필드의 **`data_hash`**가 있어 바뀐 행사만 갱신하고, 색인 단계가 변경분을 가려내는 데 쓴다.

**보관 기간**: 병합 끝에 종료 후 `tshow.merge.retention-days`가 지난 행사를 논리삭제(`archived_at`)하고, 종료일이 늘어난 행사는 되살린다.

**실측 (로컬: KOPIS 875 + 문화정보원 957 + TourAPI 264 = 소스 레코드 2,096건)**
- 행사 1,848건, 그중 여러 소스가 합쳐진 것 247건. 개선 전후: 217 → 243 → 247.
- 개선 1: 제목의 HTML 엔티티(`&amp;`, `&lt;` 등)를 정규화에서 풀었다 — 엔티티가 `amp`, `lt` 글자로 남아 유사도를 깎고 있었다.
- 개선 2: 종료일이 달라도 기간이 겹치면 같은 행사로 본다.
- 개선 3: 같은 시군구에서 제목이 사실상 같으면 장소 이름 차이를 허용한다.
- 합쳐진 예시를 눈으로 확인한 결과 오탐은 발견하지 못했다 (공연장 이름 변경, 표기·기호·연도 접두어 차이 등). 충돌은 2건.
- 이 수치는 소스 일부만 받은 로컬 데이터 기준이다. 운영의 전체 수집 후 다시 확인한다.

## 5. 순위 (일정에 맞춤)

영화의 최신작·평점 대신: 진행 중/곧 시작 가점, 마감 임박, 거리(좌표가 있을 때), 설명 있음, 여러 소스 확인됨. 가중치는 `@ConfigurationProperties`.

## 6. 평가 세트 (설계와 함께)

"이번 주말 서울 아이와 갈 곳", "무료 전시", "비 오는 날 실내 공연", "이번 달 부산 축제", "내 주변 5km 공연" 등을 케이스로 먼저 적고, 정규화·색인·검색을 바꿀 때마다 전후를 비교한다.

## 보관과 폐기 (확정: 혼합안, 2026-10-08)

Postgres는 원본 저장소이고 Qdrant는 거기서 파생한 검색용 사본이다. 둘을 다르게 처리한다.

- **Postgres: 논리삭제.** 종료 후 보관 기간(`tshow.retention.days`, 시작값 30일)이 지나면 `event.archived_at`만 찍고 행은 남긴다. 규모가 작아(월 수천 건) 부담이 없다. 소스 ID를 계속 기억하므로 **다음 수집에서 소스에 남아 있는 종료 행사가 되살아나지 않고**, 과거 기록·통계에 쓸 수 있다. 용량이 큰 원본 응답(`event_source.raw`)은 보관 기간 후 비우고 필요한 필드만 남긴다.
- **Qdrant: 물리 삭제.** 보관 기간이 지나면 해당 point를 지운다. 종료된 행사는 검색 대상이 아니고, 벡터 색인은 크기와 검색 속도에 영향을 준다. Postgres에 남아 있으니 필요하면 다시 만들 수 있다.
- **폐기 작업**(스케줄러): 보관 기간이 지난 행사에 `archived_at`을 찍고 Qdrant에서 지운다. 두 저장소가 어긋나지 않게 같은 작업에서 처리하고, 건수를 `ingest_run`에 기록한다.
- 모든 검색·조회는 `archived_at IS NULL`과 날짜 조건을 함께 건다. Qdrant에는 archived 행이 없으므로 payload 필터는 날짜만 쓴다.
- **확인 필요**: KOPIS 이용약관에 데이터 보관 기간 제한이 있는지 (사용자가 약관을 확인해 알려 주기로 함). 제한이 있으면 Postgres도 물리 삭제로 바꾼다.
- 출처 표시·집계 안내 의무는 보관 중인 데이터에도 적용한다.

## 이미지

공연·전시·축제는 시각 콘텐츠라 카드에 이미지를 보여 준다. 실측: 세 소스 모두 이미지가 있고(TourAPI 265건 전부), **모두 HTTPS로 열리며** 서비스 도메인을 Referer로 줘도 막히지 않았다 (KOPIS·문화정보원 주소는 `http://`로 오지만 같은 주소의 `https://`가 열린다 → 저장·표시 시 `https`로 바꾼다).

- **방식**: 소스가 준 URL을 그대로 링크해서 표시한다(핫링크). 우리 서버에 복사해 두거나 크기를 바꾸지 않는다. TourAPI는 목록용으로 작은 `firstimage2`를 따로 주므로(원본 `firstimage`는 1.5MB 수준이 있다) 목록에는 소스가 준 작은 이미지를 쓴다.
- **TourAPI `cpyrhtDivCd: Type3`**: 공공누리 제3유형(출처표시 + **변경금지**, 상업적 이용 가능)으로 보인다. 공식 TourAPI 문서에서 이 필드 값의 정의는 직접 확인하지 못했다(검색으로는 공공누리 제3유형의 정의만 확인). 제3유형이라면 **출처를 표시하고, 이미지를 수정·변형하지 않아야 한다.** → 이미지에 필터·글자·잘라내기를 넣지 않고 전체가 보이게(`object-fit: contain` 등) 표시하고, 이미지 근처에 출처(한국관광공사)를 표기한다.
- **KOPIS 포스터, 문화정보원 이미지**: 이용 조건(포스터의 저작권 등)을 아직 확인하지 못했다. 수익화(광고) 전에 KOPIS·문화포털의 이용약관을 확인한다. 확인 전에도 출처는 항상 표기한다.
- 이미지 URL은 `event.image_url`, 이용 조건은 `event.image_license`(소스별 유형)에 저장해서 화면이 조건에 맞게 표시하도록 한다 (코드에 소스별 분기를 박지 않고 데이터로 판단).
- 이미지가 깨지거나 없을 때를 대비해 **대체 표시**(분류별 기본 그림)를 둔다.
