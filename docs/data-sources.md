# 데이터 소스 확인 결과

2026-10-08에 인증키로 각 API를 소량 호출해서 확인한 내용이다. 키는 `.env`에만 있고 이 문서에는 적지 않는다.
값(건수 등)은 그날 기준이며, 아직 확인하지 못한 부분은 "미확인"으로 표시했다.

| 소스 | 키 발급처 | 형식 | 비고 |
|---|---|---|---|
| KOPIS | kopis.or.kr (신청 직후 이메일) | XML | 유효 1년, 3개월 미사용 시 취소. 출처 표시·집계 안내 의무 (CLAUDE.md) |
| 한국관광공사 TourAPI (국문 관광정보서비스, KorService2) | data.go.kr 일반 인증키 | JSON | 자동승인, 활용기간 24개월 |
| 한국문화정보원 한눈에보는문화정보조회서비스 | data.go.kr 일반 인증키 (TourAPI와 같은 키) | XML | 자동승인, 개발계정 일 10,000건 (활용사례 등록 시 증가 가능) |

data.go.kr 서비스의 키는 계정당 하나이지만 서비스마다 활용신청 승인이 따로 필요하다.

## 1. KOPIS (공연)

기본 주소 `http://www.kopis.or.kr/openApi/restful/`, 파라미터 `service=<키>`.

- **목록** `pblprfr?stdate=YYYYMMDD&eddate=YYYYMMDD&cpage=1&rows=N` →
  `mt20id`(공연 ID), `prfnm`(제목), `prfpdfrom/prfpdto`(`2026.10.21` 형식), `fcltynm`(공연장 이름), `poster`, `area`(시도 이름, 예: 서울특별시), `genrenm`(장르 이름, 예: 대중음악, 서양음악(클래식)), `openrun`, `prfstate`(공연예정 등)
- **상세** `pblprfr/{mt20id}` → 위 + `prfcast`(출연), `prfcrew`, `prfruntime`, `prfage`(관람 연령), `entrpsnm*`(기획·제작사), `pcseguidance`(가격 안내 **문장**: "R석 20,000원, S석 10,000원"), `sty`(줄거리, **비어 있는 경우가 있음**), `dtguidance`(시간), `styurls`(소개 이미지), `relates`(**예매처 이름과 링크**: 인터파크 등), 플래그 `child`(아동), `visit`(내한), `daehakro`, `festival`, `musicallicense`, `musicalcreate`, `updatedate`, `mt10id`(공연장 ID)
- **공연장** `prfplc/{mt10id}` → `adres`(주소), `la/lo`(**위도/경도**), `seatscale`, 주차장·식당·카페 등 편의시설 플래그, 장애인 편의시설 플래그, 공연장 홈페이지
- 확인한 점: 목록만으로는 가격·줄거리·좌표가 없어서 **작품마다 상세 + 공연장 조회가 추가로 필요**하다(공연장은 캐시 가능). 장르는 KOPIS 고유 이름이다.
- 미확인: 장르·지역 필터 파라미터 이름과 코드표(shcate, signgucode), 일일 호출 한도(응답 헤더에 없음), 포스터 이미지의 이용 조건, 박스오피스 API(`boxoffice`)

## 2. 한국관광공사 TourAPI (축제·행사)

기본 주소 `https://apis.data.go.kr/B551011/KorService2/`, 파라미터 `serviceKey=<키>&MobileOS=ETC&MobileApp=<앱 이름>&_type=json`.

- **행사 목록** `searchFestival2?eventStartDate=YYYYMMDD&numOfRows=N&pageNo=N` →
  `contentid`, `title`, `eventstartdate/eventenddate`(`20261016` 형식), `addr1/addr2`, `mapx/mapy`(**경도/위도**), `firstimage/firstimage2`, `tel`, `lDongRegnCd`/`lDongSignguCd`(**법정동 시도·시군구 코드**), `lclsSystm1~3`(분류 체계, 행사는 `EV...`), `cpyrhtDivCd`(**이미지 저작권 유형, 예: Type3**), `modifiedtime`
- 확인한 점: 확인 시점에 앞으로 시작하는 행사 총 265건. 좌표·지역 코드가 목록에 이미 있다.
- **`cpyrhtDivCd`는 공공누리 유형으로 보인다.** `Type3`가 공공누리 제3유형(출처표시 + 변경금지, 상업적 이용 가능)이라면 이미지를 수정하지 않고 출처를 표시해야 한다. 이 필드 값의 공식 정의는 직접 확인하지 못했다 (docs/index-design.md의 이미지 절 참고).
- 상세: `detailCommon2`(contentId) → `overview`(**긴 소개글**), 홈페이지, 좌표·주소·지역 코드 / `detailIntro2`(contentId, contentTypeId=15) → `sponsor`(주최), `playtime`, `eventplace`, `usetimefestival`(**요금: 무료 등**), `agelimit`, `program`(**프로그램 설명**), `bookingplace`
- 미확인: 호출 한도(응답 헤더에 없음)

## 3. 한국문화정보원 한눈에보는문화정보조회서비스 (공연·전시 등)

기본 주소 `http://apis.data.go.kr/B553457/cultureinfo/`, 파라미터 `serviceKey=<키>`. (`nopenapi/rest/publicperformancedisplays`는 "없거나 폐기" 오류였다)

- **기간별** `period2?PageNo=1&numOfrows=N&serviceTp=A&from=YYYYMMDD&to=YYYYMMDD&sortStdr=1` →
  `serviceName`(공연/전시), `seq`, `title`, `startDate/endDate`(`20251122` 형식), `place`, `realmName`(분야: 전시 등), `area`(짧은 시도 이름: 서울, 경기), `sigungu`, `thumbnail`, `gpsX/gpsY`(**경도/위도**)
- 확인한 점: 한 달 범위로 702건. 국립중앙박물관 같은 **전시**가 있어 KOPIS(공연 중심)와 보완 관계다. 가격·설명은 목록에 없다.
- 상세 `detail2?seq=<seq>` → `price`(**"무료" 등 문장**), `contents1`(설명, **비어 있는 경우가 많음**), `url`, `phone`, `imgUrl`, `gpsX/gpsY`, `placeUrl`, `placeAddr`(주소), `placeSeq`(장소 ID)
- **호출 한도: 응답 헤더 `X-RateLimit-Limit: 10000`(일 기준), `X-RateLimit-Remaining`으로 남은 수를 알 수 있다.**
- 미확인: 지역별(`area2`)·분야별(`realm2`) 오퍼레이션, `serviceTp` 값의 의미(A 외)

## 4. 세 소스를 합칠 때 확인된 차이와 과제

| 항목 | KOPIS | TourAPI | 문화정보원 |
|---|---|---|---|
| 날짜 형식 | `2026.10.21` | `20261016` | `20251122` |
| 지역 | 시도 이름(서울특별시) | 법정동 코드(11, 710) | 짧은 시도 이름 + 시군구(서울, 용산구) |
| 좌표 | 공연장 조회에서(위도 `la`, 경도 `lo`) | `mapx`=경도, `mapy`=위도 | `gpsX`=경도, `gpsY`=위도 |
| 분류 | KOPIS 장르 이름 | 분류 체계 코드(`EV01…`) | 분야 이름(`realmName`) |
| 가격 | 문장(상세) | 미확인 | 목록에는 없음 |
| 이미지 | 포스터 | 대표 이미지(+저작권 유형) | 썸네일 |

- 날짜는 모두 하나의 시각 형식으로, 지역은 법정동 코드(시도 2자리 + 시군구 5자리)로, 좌표는 위도/경도 순서를 통일해 저장해야 한다. 이름으로 들어오는 지역(KOPIS·문화정보원)은 시도·시군구 이름 → 코드 변환표가 필요하다.
- 분류는 소스별 이름을 우리 표준 분류로 옮기는 표가 필요하다 (소스 이름 목록은 데이터를 더 받아서 만든다).
- 같은 공연이 KOPIS와 문화정보원에 중복될 수 있어 제목·장소·기간으로 중복 판정이 필요하다. 아직 실제 중복 정도는 확인하지 않았다.
- 가격은 소스에 따라 문장이라 "무료/유료"는 문장에서 판정하거나 AI로 정리해야 할 수 있다.

## 5. 한 달 범위(오늘~30일) 실측 (2026-10-08)

| 소스 | 건수 | 분류 분포 |
|---|---|---|
| KOPIS | 2,190건 (목록 22쪽×100) | 서양음악(클래식) 681, 대중음악 414, 연극 379, 뮤지컬 363, 한국음악(국악) 140, 무용 78, 서커스/마술 74, 복합 60, 대중무용 1 / 상태: 공연예정 1,822, 공연중 368 |
| 문화정보원 | 702건 (공연 575 + 전시 127) | realmName: 음악/콘서트 348, 전시 130, 연극 104, 뮤지컬/오페라 51, 무용/발레 26, 국악 22, 기타 16, 아동/가족 4, 행사/축제 1 |
| TourAPI 행사 | 265건 | 분류 체계 `EV…` 코드(상위: EV030400 60, EV010600 41, EV010200 35, …), 이미지 저작권 유형은 전부 `Type3` |

### 데이터 품질에서 확인된 점 (표·규칙을 코드에 박지 말아야 하는 이유)

- **지역 이름이 일정하지 않다.** KOPIS에 `전남광주통합특별시`(새 행정구역 이름)와 `해외`가 있고, 문화정보원은 `서울`과 `서울시`가 섞여 있다. (TourAPI의 시도 코드 `36110`은 오류가 아니라 **세종특별자치시의 정식 시도 코드**다 — 공식 코드표 `ldongCode2`로 확인.) → 지역 변환은 공식 코드표(`taxonomy/regions.csv`, `scripts/gen_regions.py`로 생성) + **별칭 파일**(`region-aliases.yml`)로 하고, 변환하지 못한 값은 오류가 아니라 **"매핑 안 된 값" 리포트**(`ingest_run.unmapped`)로 남겨 표를 고칠 수 있게 한다.
- **분류 이름이 소스마다 다르다.** (예: KOPIS `서양음악(클래식)`·`대중음악`, 문화정보원 `음악/콘서트`, TourAPI `EV010600`) → 표준 분류 변환표(리소스 파일)가 필요하고, 새 분류가 나오면 코드가 아니라 표를 고친다.
- **중복이 많다.** 문화정보원 공연 575건 중 **320건(약 56%)이 KOPIS와 제목+시작일이 일치**했다(제목의 `[지역]` 꼬리표 위치만 다름). 일치하지 않는 251건은 KOPIS에 없거나 제목 표기 차이(`[대학로] 히든퍼즐 20260701`처럼 제목에 날짜가 붙음)일 수 있다. → 제목 정규화(꼬리표·날짜·공백 제거) + 장소 이름 유사도 + 날짜로 중복을 판정해야 한다.
- **설명이 없는 항목이 많다.** 하루치 실측에서 KOPIS 공연 368건 중 **설명(`sty`)이 있는 것은 33건(약 9%)** 뿐이었다. 문화정보원 `contents1`도 비어 있는 경우가 많다. TourAPI는 `overview`가 풍부하다. 설명이 없을 때의 임베딩 텍스트 구성과, 소스를 합칠 때 설명은 있는 쪽을 채택하는 규칙이 필요하다.
- **KOPIS는 작품마다 상세 + 공연장 조회가 필요하다.** 한 달 2,190건이면 상세 2,190회 + 공연장(캐시 가능) 호출이 든다. 첫 수집은 호출이 많고, 이후에는 `updatedate` 기준 변경분만 갱신한다.

## 6. KOPIS 호출 제한과 박스오피스 (2026-10-08 확인)

- **조회 기간은 `stdate`부터 `eddate`까지 최대 30일 차이**다. 31일 이상은 `400 Request Blocked`(HTML 오류 페이지)로 차단된다. 6개월 수집은 30일 단위로 나눠 호출한다.
- **짧은 시간에 호출이 몰리면 일시적으로 `400`으로 차단**된다(같은 요청이 이전엔 되었다가 막혔고, 잠시 후 풀림). 호출 사이 간격을 두고 `400`/`5xx`는 대기 후 재시도한다.
- **박스오피스** `boxoffice?stdate=&eddate=&catecode=&area=&ststype=week` → `cate`(분류), `rnum`(순위), `prfnm`, `prfpd`(기간), `prfdtcnt`(공연 횟수), `area`, `prfplcnm`(공연장), `seatcnt`(좌석 수), `poster`, `mt20id`. 관객 수·금액 자체는 응답에 없고 **순위 위주**다. 사용 시 집계 안내 표시 의무가 있다.

## 7. 수집기 구현에서 확인된 점 (2026-10-08)

- **문화정보원** `period2`는 **조회 기간 한도가 없다.** 1년 범위도 호출되며 건수는 30일 705건 → 6개월 957건 → 1년 971건으로, 데이터가 가까운 시기에 몰려 있다 (먼 미래 일정은 거의 없다). 6개월을 한 구간으로 조회한다(`window-days: 400`).
- **TourAPI** `searchFestival2`는 `eventStartDate`(시작일) 기준으로만 조회된다. 오늘 이후 시작 265건, 90일 전부터 518건, 180일 전부터 744건. 진행 중인 행사를 얻으려고 **180일 전부터 조회하고 기간이 겹치는 것만 남긴다**(`lookback-days: 180`).
- **TourAPI 목록 이미지**: `firstimage`(원본, 수 MB 가능)와 `firstimage2`(작은 이미지)가 있어 작은 쪽을 저장한다. `homepage`는 HTML(`<a href=...>`)로 올 때가 있어 주소만 뽑는다.
- **KOPIS 하루치 품질(368건)**: 시도 코드 100%, 좌표 100%, 예매 링크 100%, 이미지 100%, 연령 99.7%, 출연진 76%, 기획사 79%, 시군구 코드 98.9%(4건은 인천 신설 구·세종 등 코드표에 없는 값), **설명 9%**.
- **가격 판정(하루치)**: 유료 352, 무료 13, 알 수 없음 3.
